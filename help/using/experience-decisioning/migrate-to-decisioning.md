# 決定への移行のメリット {#migrate-to-decisioning}

>[!BEGINSHADEBOX]

**このページでは、**&#x200B;意思決定管理に対するDecisioningの機能と利点、および使用可能な移行ツールについて説明します。これにより、移行するかどうかを決定できます。

>[!ENDSHADEBOX]

## 意思決定とは？ {#what-is-decisioning}

Journey Optimizer Decisioningは、将来の他のオブジェクト（ジャーニーなど）を決定するための基盤を構築する決定機能の拡張です。 この新機能は、オーサリングと管理を合理化するための主要なワークフローコンセプトを統合し、意思決定の検証を導入し、意思決定アイテムを動的なアイテムレンダリングのためのスキーマベースのアプローチに移行します。

Adobe Journey Optimizerの次世代意思決定フレームワークと機能セットを利用すれば、利用可能なデータ、インテリジェンス、顧客のコンテキストを活用して、顧客一人ひとりに最適なエクスペリエンスを決定し、ビジネス価値を最適化できます。 [詳細情報](gs-experience-decisioning.md)

## Decisioningに移行する理由 {#why-migrate}

意思決定は、従来の意思決定管理フレームワークよりも大きな機能と利点があります。

### AIおよびマシンラーニング能力

* **カスタム指標**: AI モデルにカスタム最適化指標を使用する機能。 これにより、[Customer Journey Analytics](https://experienceleague.adobe.com/ja/docs/analytics-platform/using/cja-overview/cja-overview){target="_blank"}とのレポートの相互運用性が向上し、両方のプラットフォームでレポートを標準化し、データの一貫性と信頼性を向上させます。 シームレスな統合により、パフォーマンス指標をより明確に把握できます。また、シンプルな指標の作成、オーディエンスの公開、Insight Builderを使用した高度な質問、レポートのスケジュール設定などの新機能も追加されます。

* **上昇率の測定**:AI モデルで探索と悪用トラフィックを視覚化する機能。 これにより、マーケターやデータサイエンティストは、AIを利用して、長期的なモデルのパフォーマンスや新しい顧客オファーの見つけやすさを向上させる方法を定量化できます。 トラフィック配分の透明性により、AIによる意思決定に対する信頼を構築し、学習とパフォーマンスの両方に向けて長期的に最適化できるようになります。 [詳細情報](ranking/auto-optimization-model.md#lift)

* **AI式ビルダー**:AI モデル スコア出力を既存の数式機能に適用する機能。 これにより、マーケターはAI出力を決定論的なルールや重みづけにシームレスに組み合わせて、より詳細な最適化戦略を策定できるようになります。これにより、マシンラーニング（機械学習）のインテリジェンスを活用しながら、コントロールと柔軟性が向上します。 [詳細情報](ranking/ranking-formulas.md)

### 実験

オファー、特定のオファーの側面、ランキング方法を実験する機能。 これにより、マーケターはクリエイティブ、適格性、ランキングロジックに関して管理された実験を実行し、パフォーマンスの高いバリエーションを特定できます。これにより、学習サイクルを加速させ、意思決定システムの継続的な最適化を促進できます。

### 拡張レポート

Funnelの主な要素に対する意思決定項目と選択戦略のパフォーマンスを文書化したダッシュボード。 直観的ですぐに使える意思決定ダッシュボードを使用して、オファーやコンテンツの配信、ディスプレイとクリックのエンゲージメント、フォールバックの使用率、AIやマシンラーニングによるランキングモデルからの上昇率など、主要なKPIに対するキャンペーンやジャーニーのパフォーマンス値をすばやく確認できます。 [詳細情報](cja-reporting.md)

### 業務効率

* **サンドボックスのコピー**：サンドボックス間でオブジェクトをコピーする機能（開発から実稼動など）。 これにより、環境間での決定ロジック、オファー、設定オブジェクトのシームレスな移行が可能になり、セットアップ時間が短縮され、ヒューマンエラーが最小限に抑えられるため、デプロイメントとテストのワークフローが簡素化されます。 [詳細情報](../configuration/copy-objects-to-sandbox.md)

* **スキーマベースのアイテム カタログ管理**: スキーマにリンクされたデータセットに対して決定項目を直接定義および管理し、動的な更新とシンプルなガバナンスを実現します。 これにより、決定項目と基礎となるデータソースを同期し、コンテンツの正確性を確保して、より迅速な更新を可能にし、大規模なガバナンスをサポートすることで、カタログ管理が合理化されます。 [詳細情報](items.md)

* **場所に依存しない決定**：決定ロジックをプレースメント/場所で再利用し、決定の選択を配信から切り離す機能。 これにより、単一の決定モデルを使用して、複数の配置やサーフェス（web、アプリ、電子メールなど）に対応し、ロジックを一元化し、クロスチャネルのパーソナライゼーション作業を高速化することで、再利用性と効率性を向上できます。 [詳細情報](placements.md)

* **再利用可能なコンテンツフラグメント**: JSONまたはHTML コンテンツブロック（タイトル、ヘッダー、フッター、CTAなど）を一度定義し、複数のオファーオブジェクト内で参照できます。 これにより、共有コンポーネントを一元管理し、オファーをまたいで自動的に更新できるようになり、コンテンツのオーサリングとガバナンスが合理化されます。 [詳細情報](../content-management/fragments.md)

### 今後の機能

* **チャネル決定**：決定ロジックを使用して、単一チャネル内の最適なオファーだけでなく、エンゲージメントに最適なチャネル（電子メールとプッシュとwebなど）を決定する機能。 これにより、配信先だけでなく、メッセージの配信先も最適化して、顧客体験を向上させることができます。

* **メッセージの最適化**: AIまたはルールベースのアプローチを使用して、各プロファイルのメッセージコンテンツを最適化し、エンゲージメントとコンバージョンの成果を向上させる機能。 これにより、マーケターは、オーディエンスの属性やパフォーマンスデータにもとづいて、トーン、イメージ、レイアウトを動的に調整できます。

* **ジャーニーパスの最適化**：実験結果、リアルタイムのコンテキスト、ルール、コンバージョン傾向などにもとづいて、プロファイルがどのジャーニーパスに従うべきかを決定する機能。 これにより、最適なジャーニーブランチを通じてプロファイルをインテリジェントにルーティングし、各ユーザーに適切な頻度とコンテンツを提供できるようになります。

* **ジャーニー決定**: プロファイルが複数の対象に適格である場合に、複数のジャーニー間で調停を行い、最も価値のあるジャーニーまたは関連性のあるジャーニーを選択できるようにする機能。 これにより、各プロファイルに対して最も優先度の高いジャーニーをランキングして選択することで、メッセージの競合や過剰なメッセージを防ぐことができます。

### その他の機能

* **ポリシーの適用**: Decisioning内で[&#x200B; データ使用ラベル付けと適用（DULE） &#x200B;](https://experienceleague.adobe.com/ja/docs/experience-platform/data-governance/labels/overview){target="_blank"}および[同意](../action/consent.md)などの機能を使用するためのビジネスユーザーの権限を付与し、Decisioning ワークフロー全体でプライバシーシールド保護を有効にします。 これにより、意思決定において、データ使用ポリシーと顧客の同意設定が自動的に尊重されるようになります。

* **ネイティブメッセージングチャネルのサポート**：複数のチャネルにまたがる単一のフレームワーク内での統合されたメッセージと決定：[&#x200B; コードベースのエクスペリエンス &#x200B;](../code-based/get-started-code-based.md)、[電子メール &#x200B;](../email/get-started-email.md)、[SMS](../mobile/get-started-mobile.md)、[&#x200B; プッシュ通知](../push/get-started-push.md)。 直感的なUI サポートにより、ユーザーはメッセージ作成ワークフローに意思決定コンポーネントを直接挿入できます。

* **Experience Platform データセット ルックアップ**: [Adobe Experience Platform データセット &#x200B;](https://experienceleague.adobe.com/ja/docs/experience-platform/catalog/datasets/overview){target="_blank"}を、オファーの選択ルール、ランキング、パーソナライズされたオファーコンテンツ内に直接アップロードして参照する機能。 これにより、意思決定ロジックで動的な外部データソースを使用できるようになり、パーソナライゼーションとターゲティングの柔軟性が向上します。 [詳細情報](../data/lookup-aep-data.md)

* **スケーラビリティとパフォーマンス**：意思決定計算をハブからエッジに移動させるアーキテクチャの強化により、トラフィックの多いユースケースの遅延を大幅に減らし、スループットを向上させます。

## ユースケースの例 {#use-cases}

| 使用例 | 意思決定管理 | 決定 |
|----------|---------------------|-------------|
| **複数プレースメント戦略** | 特定のプレースメント（webやメールの場所など）に関連付けられた意思決定ロジック | 単一の戦略が、ホームページとモバイルアプリの両方の機能を強化する |
| **一貫したオファー属性** | 各オファーは独自の属性を手動で管理します。スキーマレベルの一貫性はありません | マーケターは、「discountType」と「offerValue」を1回定義します。すべてのオファーは、これらのフィールドを自動的に継承します |
| **動的AI ランキング** | ランキングは、モデル出力または静的ルールのみに依存します | マーケターは、売上とエンゲージメント目標のバランスをとるために、重み付け（60%のAI コンバージョンスコア+40%の利益率）を調整できます |
| **A/B テスト戦略** | 組み込みのテスト機能のサポートなし | チームは、「AI + ビジネスルール」が「優先度ベースのランキング」を上回るかどうかをA/B テストできます |
| **カスタム AI指標** | クリックの傾向に対してのみ最適化し、モデルの探索や上昇の可視性はありません | Retailerが「購入の可能性」モデルをトレーニングし、新製品と既知の製品のリフトをモニタリングする |
| **コンテンツの再利用性** | 各オファーは、完全なコンテンツを独立して保存します | ヘッダーまたはCTAを更新すると、数百のオファーに自動的に反映されます |
| **統合オーサリング** | 意思決定とメッセージは統合が限定的な個別のフレームワークで行われます | マーケターがメッセージエディターを離れることなく、パーソナライズされたオファーをメールに挿入 |
| **プライバシーコンプライアンス** | 実施するには、エンジニアリング部門やデータチームとの手作業での調整が必要 | マーケターは、同意設定によって特定のプロファイルが自動的に除外されることを理解したうえで、オファールールを作成します |
| **リアルタイム在庫** | 静的データ：外部データセットやコンテクストにもとづくデータセットの使用に柔軟性がない | 商品在庫データセットを使用して、在庫切れ商品のオファーをリアルタイムで除外します |
| **パフォーマンスを拡大** | 待ち時間の多いハブでの意思決定 | レスポンスタイムが100 ミリ秒未満の何百万件ものリクエストに対して、リアルタイムでパーソナライズ |

## 移行ツール {#migration-tooling}

決定管理エンティティをDecisioningに移行するには、**移行ツール API**&#x200B;の包括的なセットを使用できます。 これらのAPIは、自動化された依存関係の解決機能とロールバック機能により、サンドボックス間のシームレスな移行を可能にします。

移行ツール APIを使用すると、次のことが可能になります。

* ソースとターゲットのサンドボックス間の依存関係を&#x200B;**分析**
* **異なるスコープでの移行** - サンドボックス、オファー、または決定レベル
* 問題が検出された場合、**ロールバック移行**

認証、エンドポイント、リクエスト/レスポンスの例、ステップバイステップのワークフローなど、完全なAPI ドキュメントについては、[このページ &#x200B;](decisioning-migration-api.md)を参照してください。
